# 디버깅 — 물 부족

[프로그래머스 문제 링크](https://school.programmers.co.kr/learn/courses/30/lessons/340202)

## 문제 요약
월별 물 사용량 변화율(change)을 적용해서 — 몇 달 뒤 저수지 물(storage)이 
부족해지는지 반환. 가뭄 끝까지 충분하면 -1 반환.
1줄만 수정해서 버그 고치는 디버깅 문제.

- change[i] 양수 → 전 달 대비 증가
- change[i] 음수 → 전 달 대비 감소
- 매달 물 사용량은 소수점 버린 정수로 계산

## 원본 코드 (버그 있음)
\`\`\`python
def solution(storage, usage, change):
    total_usage = 0
    for i in range(len(change)):
        usage = total_usage * change[i]/100   # ← 버그
        total_usage += usage
        if total_usage > storage:
            return i
    return -1
\`\`\`

## 풀이
\`\`\`python
def solution(storage, usage, change):
    total_usage = 0
    for i in range(len(change)):
        usage = int(usage * (1 + change[i]/100))
        total_usage += usage
        if total_usage > storage:
            return i
    return -1
\`\`\`

`usage = total_usage * change[i]/100`을 
`usage = int(usage * (1 + change[i]/100))`로 변경.

## 막힌 부분

### 1차 시도 — `(1 + ...)` 누락
\`\`\`python
usage = usage * change[i]/100
\`\`\`

문제: change[i]만 곱하니까 — 변화량만 계산되고 원래 사용량(usage) 자체가 반영 안 됨.
- change[i] = 10 → `usage × 0.10` (사용량의 10%만 나옴)
- 원래 의도는 — usage에 10% 증가 적용 → `usage × 1.10`

`(1 + ...)` 형태로 감싸야 — "기존 값 + 변화" 의미.

### 2차 시도 — 부호 잘못
\`\`\`python
usage = usage * (1 - change[i]/100)
\`\`\`

`-` 사용해서 — change 부호와 의미가 반대로 적용됨:
- `change[i] = 10` (증가 의도) → `usage × 0.9` (감소 결과)
- `change[i] = -10` (감소 의도) → `usage × 1.1` (증가 결과)

### 3차 시도 — 정수 변환 누락
\`\`\`python
usage = usage * (1 + change[i]/100)
\`\`\`

부호는 고쳤지만 — 소수가 그대로 남아 문제 조건("소수점 이하 버린 정수") 미충족.

### 최종 — `int()` 추가하여 통과
\`\`\`python
usage = int(usage * (1 + change[i]/100))
\`\`\`

## 배운 점

### 증감 비율 수식 패턴
- N% 증가 → `× (1 + N/100)`
- N% 감소 → `× (1 - N/100)`
- 변화율이 부호 포함이면 (양수=증가, 음수=감소) → `× (1 + 변화율/100)` 하나로 통합

이번 문제처럼 — change[i]가 양수/음수 다 가능할 땐 `+` 부호로 통합하는 게 표준.

### `int()` 함수 — 소수점 버림
\`\`\`python
int(1.9)    # 1 (버림, 반올림 아님)
int(1.1)    # 1
int(0.99)   # 0
\`\`\`

`round()`와 차이:
- `round(1.5)` → 2 (반올림)
- `int(1.5)` → 1 (버림)

문제에서 "소수점 이하를 버린 정수" → `int()` 사용.

### 디버깅 시 원본 코드 분석의 중요성
원본의 의도를 정확히 파악해야 어디가 버그인지 보임.
- `total_usage` — 누적 사용량 (저수지에서 빠져나간 총량)
- `usage` — 매월 사용량 (전 달 대비 변화 적용)
- 원본은 `total_usage * change[i]/100`로 계산 — 의미상 잘못
  (누적 사용량에 변화율 적용은 문제 의도와 다름)

올바른 의미: **이번 달 사용량 = 지난 달 사용량 × (1 + 변화율)**

### 문제 조건 작은 부분 놓치지 않기
"매달 물 사용량은 소수점 이하를 버린 정수로 계산" — 이 한 문장이 
`int()` 필요 신호. 큰 흐름만 보고 작은 조건 놓치면 — 통과 못 함.

## 풀이 흐름 시뮬레이션
입력: `storage=100, usage=10, change=[10, -10, 10, -10]`

\`\`\`
i=0: usage = int(10 * 1.10) = 11
     total_usage = 0 + 11 = 11
     11 > 100? No

i=1: usage = int(11 * 0.90) = 9
     total_usage = 11 + 9 = 20
     20 > 100? No

i=2: usage = int(9 * 1.10) = 9
     total_usage = 20 + 9 = 29
     29 > 100? No

i=3: usage = int(9 * 0.90) = 8
     total_usage = 29 + 8 = 37
     37 > 100? No

루프 종료 → return -1 (가뭄 끝까지 물 충분)
\`\`\`
