# 재구매가 일어난 상품과 회원 리스트 구하기

[프로그래머스 문제 링크](https://school.programmers.co.kr/learn/courses/30/lessons/131536)

## 문제 요약
ONLINE_SALE 테이블에서 — 동일한 회원이 동일한 상품을 재구매한 데이터 조회.
- 회원 ID + 상품 ID 출력
- 회원 ID 오름차순, 같으면 상품 ID 내림차순

## 접근 방법
"재구매" = 같은 회원이 같은 상품을 2번 이상 구매
→ USER_ID + PRODUCT_ID 조합으로 그룹화
→ 그룹의 행 개수가 2 이상인 경우만 (HAVING 사용)

## 풀이
\`\`\`sql
SELECT USER_ID, PRODUCT_ID
FROM ONLINE_SALE
GROUP BY USER_ID, PRODUCT_ID
HAVING COUNT(*) > 1
ORDER BY USER_ID, PRODUCT_ID DESC;
\`\`\`

## 막힌 부분
한 번에 통과. 다만 — "재구매" 조건을 어떻게 표현할지 고민 시간 길었음.

처음에 — `WHERE COUNT(*) > 1` 시도하려 했으나, 집계 함수는 WHERE에서 못 씀을 인지.
→ HAVING 사용으로 해결.

## 배운 점

### WHERE vs HAVING 차이
- **WHERE** — 그룹화 **전** 필터링 (개별 행 기준)
- **HAVING** — 그룹화 **후** 필터링 (집계 결과 기준)

\`\`\`sql
-- 잘못 (WHERE에 집계 함수 못 씀)
WHERE COUNT(*) > 1

-- 올바름
HAVING COUNT(*) > 1
\`\`\`

집계 함수(COUNT, SUM, AVG, MAX, MIN)로 필터링 — 항상 HAVING 사용.

### SQL 실행 순서 — 중요한 패턴
\`\`\`
FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY
\`\`\`

WHERE는 GROUP BY 전 → 개별 행 필터링.
HAVING은 GROUP BY 후 → 그룹 단위 필터링.

이 순서가 — WHERE/HAVING 구분의 근본 이유.

### GROUP BY 다중 컬럼
\`\`\`sql
GROUP BY USER_ID, PRODUCT_ID
\`\`\`

두 컬럼 **조합**으로 그룹화. 즉:
- USER_ID=1, PRODUCT_ID=10 → 그룹 A
- USER_ID=1, PRODUCT_ID=20 → 그룹 B (다른 그룹)
- USER_ID=2, PRODUCT_ID=10 → 그룹 C

이번 문제 — 같은 회원이 같은 상품 재구매 = 같은 (USER_ID, PRODUCT_ID) 조합 2개 이상.

### COUNT(*) — 그룹 내 행 개수
\`\`\`sql
HAVING COUNT(*) > 1
\`\`\`

각 그룹의 행 개수가 1보다 큰 경우 (2 이상).
즉, 같은 조합이 2번 이상 등장 = 재구매.
