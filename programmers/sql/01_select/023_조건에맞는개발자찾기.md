# 조건에 맞는 개발자 찾기

[프로그래머스 문제 링크](https://school.programmers.co.kr/learn/courses/30/lessons/276034)

## 문제 요약
- SKILLCODES — 스킬의 이름, 범주, 코드(2진수 비트로 구성)
- DEVELOPERS — 개발자 정보, SKILL_CODE(보유 스킬을 비트 조합으로 표현)

Python 또는 C# 스킬을 가진 개발자의 ID, EMAIL, FIRST_NAME, LAST_NAME 조회.
- ID 오름차순

## 접근 방법 — 비트 연산
개발자의 SKILL_CODE — 비트 조합으로 여러 스킬 동시 표현.

예시:
- Python CODE = 16 (000010000) — 5번 비트
- 개발자 SKILL_CODE = 400 (110010000) — 256 + 128 + 16

→ `SKILL_CODE & 16` 결과가 0보다 크면 Python 보유.

## 풀이
\`\`\`sql
SELECT DISTINCT D.ID, D.EMAIL, D.FIRST_NAME, D.LAST_NAME
FROM DEVELOPERS D
JOIN SKILLCODES S ON D.SKILL_CODE & S.CODE > 0
WHERE S.NAME IN ('Python', 'C#')
ORDER BY D.ID;
\`\`\`

## 막힌 부분
"SQL에서 비트 연산을 어떻게 쓰는지" 처음 만남. 

AND 연산 자체는 이미 학습한 개념이지만 — **SQL에서 `&`로 비트 AND 수행 후 결과 비교** 패턴은 처음.

### 핵심 깨달음
- AND 연산은 — 양쪽 다 1인 비트만 1로 살림
- 결과가 0보다 크다 = 어딘가 둘 다 1인 비트가 있다 = 해당 스킬 보유

## 배운 점

### 비트 연산 — SQL 응용
이미 학습한 AND 연산을 — SQL에서 `&`로 사용.

\`\`\`sql
컬럼 & 값 > 0    -- 그 비트가 1인지 확인
\`\`\`

예시:
\`\`\`
SKILL_CODE = 400 (110010000)
Python CODE = 16 (000010000)

   110010000
 & 000010000
 -----------
   000010000  = 16 (>0) → Python 보유

Java CODE = 2 (000000010)

   110010000
 & 000000010
 -----------
   000000000  = 0 → Java 미보유
\`\`\`

### 비트 플래그 패턴
이 문제처럼 — **여러 boolean을 한 컬럼에 비트로 저장**하는 패턴.

실무 활용 예 — 권한 관리:
\`\`\`
READ   = 1 (001)
WRITE  = 2 (010)
DELETE = 4 (100)

사용자 권한 = 3 (011) → READ + WRITE 보유
사용자 권한 = 7 (111) → 모든 권한 보유

권한 체크: 사용자권한 & READ > 0 ?
\`\`\`

여러 컬럼·테이블 분리 안 하고 — 한 컬럼에 효율적으로 저장.

### JOIN 조건에 비트 연산
\`\`\`sql
JOIN SKILLCODES S ON D.SKILL_CODE & S.CODE > 0
\`\`\`

JOIN의 ON 절은 — 단순 컬럼 일치만 가능한 게 아니라 **조건식** 모두 가능.
비트 연산 결과로 JOIN 조건 구성.

### `DISTINCT` — 중복 제거
한 개발자가 Python과 C# 둘 다 보유 시:
- Python으로 매칭 → 한 줄
- C#으로 매칭 → 한 줄
→ 같은 개발자 두 번 나옴

`DISTINCT`로 중복 제거. 결과를 유일하게.

### `IN` 연산자 — 여러 값 비교
\`\`\`sql
WHERE S.NAME IN ('Python', 'C#')
\`\`\`

이전 학습한 IN의 기본 사용 패턴.
\`WHERE S.NAME = 'Python' OR S.NAME = 'C#'\`과 동일하지만 깔끔.

## 융합 학습 — 다른 영역 지식의 SQL 응용
이번 학습 — **AND 연산(컴퓨터 구조 기초)** 을 SQL에 응용.

핵심 깨달음:
- 한 영역에서 배운 개념 → 다른 영역에서 응용
- SQL은 데이터 조작 + 연산 둘 다 가능
- ON 절, WHERE 절에 — 단순 비교 아니라 복잡한 표현식 사용 가능

데이터 엔지니어링에서 — 이런 융합 사고가 자주 필요.
권한 관리, 플래그 처리, 비트 압축 등에서 비트 연산 자주 사용.

## 다른 풀이 — 서브쿼리 (참고)
\`\`\`sql
SELECT ID, EMAIL, FIRST_NAME, LAST_NAME
FROM DEVELOPERS
WHERE SKILL_CODE & (SELECT CODE FROM SKILLCODES WHERE NAME = 'Python') > 0
   OR SKILL_CODE & (SELECT CODE FROM SKILLCODES WHERE NAME = 'C#') > 0
ORDER BY ID;
\`\`\`

각 스킬 CODE를 서브쿼리로 가져옴. JOIN보다 길지만 의미는 동일.

JOIN 방식이 더 깔끔하고 확장성 좋음 (스킬 추가 시 WHERE의 IN만 수정).

## 데이터베이스 설계 관점 (참고)
이 문제 — 비트 플래그로 스킬 저장.

실무 설계 — 별도 테이블 분리도 흔함:
\`\`\`
DEVELOPER_SKILL 테이블:
  DEVELOPER_ID | SKILL_NAME
  1            | Python
  1            | C#
  2            | Java
\`\`\`

장단점:
- 비트 플래그 — 한 컬럼에 효율 저장, 쿼리 빠름. 다만 — 새 스킬 추가 어려움(32/64비트 한계)
- 별도 테이블 — 유연성 좋음, 확장 가능. 다만 — JOIN 비용

상황에 맞게 선택. 권한 같은 — 종류 적고 자주 체크하는 경우는 비트 플래그가 적합.
