# 상위 n개 레코드

[프로그래머스 문제 링크](https://school.programmers.co.kr/learn/courses/30/lessons/59405)

## 문제 요약
ANIMAL_INS 테이블에서 — 가장 먼저 들어온 동물(DATETIME이 가장 빠른)의 이름 조회.

## 접근 방법
"가장 먼저" = 정렬 후 맨 위 1개
→ ORDER BY로 시간 순 정렬 + LIMIT 1로 1개만

## 풀이
\`\`\`sql
SELECT NAME
FROM ANIMAL_INS
ORDER BY DATETIME
LIMIT 1;
\`\`\`

## 막힌 부분

### 1차 시도 — GROUP BY + HAVING
\`\`\`sql
SELECT NAME 
FROM ANIMAL_INS
GROUP BY NAME
HAVING MIN(DATETIME)
\`\`\`

문제 두 가지:
1. **GROUP BY 사용 의도 잘못** — 같은 이름끼리 그룹화할 필요 없음. 1개 행만 찾으면 됨.
2. **HAVING의 사용법 잘못** — `HAVING MIN(DATETIME)`은 조건이 아니라 값. HAVING은 비교 조건이 와야 함.

### 핵심 깨달음
- "가장 ~한 1개" = `ORDER BY ~ LIMIT 1`
- GROUP BY는 — 그룹별 집계가 필요할 때만 사용

## 배운 점

### `LIMIT` 함수 — 상위 N개 반환
\`\`\`sql
SELECT * FROM 테이블 LIMIT 5;     -- 상위 5개
SELECT * FROM 테이블 LIMIT 1;     -- 상위 1개
\`\`\`

ORDER BY와 함께 자주 사용:
\`\`\`sql
SELECT * FROM 테이블 ORDER BY 점수 DESC LIMIT 1;    -- 최고 점수 1개
SELECT * FROM 테이블 ORDER BY 날짜 LIMIT 1;          -- 가장 빠른 1개
\`\`\`

### "가장 ~한" 패턴 — 두 가지 풀이

**방법 1 — ORDER BY + LIMIT (이번 풀이, 권장)**
\`\`\`sql
SELECT NAME
FROM ANIMAL_INS
ORDER BY DATETIME
LIMIT 1;
\`\`\`

**방법 2 — 서브쿼리 + MIN/MAX**
\`\`\`sql
SELECT NAME
FROM ANIMAL_INS
WHERE DATETIME = (SELECT MIN(DATETIME) FROM ANIMAL_INS);
\`\`\`

비교:
| | ORDER BY + LIMIT | 서브쿼리 + MIN |
|---|---|---|
| 가독성 | 직관적 | 약간 복잡 |
| 동작 | 정렬 후 1개 | 최솟값 찾고 그 행 |
| 타이 처리 | 1개만 | 같은 시간이면 다 나옴 |

ORDER BY + LIMIT이 더 간단. 다만 — 서브쿼리도 응용 패턴으로 자주 사용.

### HAVING의 정확한 사용법
HAVING은 — **비교 조건**이 와야 함.

\`\`\`sql
HAVING COUNT(*) > 1        -- O (비교 조건)
HAVING MIN(DATETIME)       -- X (조건이 아니라 값)
HAVING SUM(...) >= 100     -- O
HAVING AVG(...) < 50       -- O
\`\`\`

값만 적으면 — DB가 "어떤 비교?" 모름.

### GROUP BY 사용 시점
GROUP BY는 — **그룹별로 집계**할 때 사용.
- 식당별 평균 점수 → GROUP BY 식당
- 카테고리별 개수 → GROUP BY 카테고리

단순히 "1개 행" 찾는 데는 GROUP BY 불필요.

### "가장 ~한" 패턴 사고법
1. **정렬 가능한 기준 식별** (시간, 점수, 가격 등)
2. **방향 결정** (가장 빠른 = ASC, 가장 큰 = DESC)
3. **1개만 가져오기** (LIMIT 1)
