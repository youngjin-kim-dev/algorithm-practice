# 업그레이드 된 아이템 구하기

[프로그래머스 문제 링크](https://school.programmers.co.kr/learn/courses/30/lessons/273711)

## 문제 요약
- ITEM_INFO — 아이템 정보 (ID, NAME, RARITY, PRICE)
- ITEM_TREE — 아이템 관계 (ITEM_ID, PARENT_ITEM_ID)
  - PARENT_ITEM_ID = 업그레이드 전 아이템
  - ITEM_ID = 업그레이드 후 (자식) 아이템

RARE 아이템들의 **다음 업그레이드 아이템**(자식)의 ID, NAME, RARITY 조회.
- ITEM_ID 기준 내림차순 정렬

## 접근 방법
1. RARE 아이템 찾기 → ITEM_INFO에서 RARITY = 'RARE'
2. 그 아이템들의 자식 찾기 → ITEM_TREE에서 PARENT_ITEM_ID 매칭
3. 자식 아이템의 정보 가져오기 → ITEM_INFO에 다시 JOIN

→ **ITEM_INFO 두 번 JOIN 필요** (부모용, 자식용)

## 풀이
\`\`\`sql
SELECT C.ITEM_ID, C.ITEM_NAME, C.RARITY
FROM ITEM_INFO A
JOIN ITEM_TREE B ON A.ITEM_ID = B.PARENT_ITEM_ID
JOIN ITEM_INFO C ON B.ITEM_ID = C.ITEM_ID
WHERE A.RARITY = 'RARE'
ORDER BY C.ITEM_ID DESC;
\`\`\`

**구조 분석**:
- **A** — 부모 아이템 (ITEM_INFO)
- **B** — 트리 관계 (ITEM_TREE)
- **C** — 자식 아이템 (ITEM_INFO, 같은 테이블 두 번째 JOIN)

## 막힌 부분

### 1차 시도 — 자식의 정보 가져오는 방법 모름
\`\`\`sql
SELECT B.ITEM_ID, A.ITEM_NAME, A.RARITY
FROM ITEM_INFO A 
JOIN ITEM_TREE B ON A.ITEM_ID = B.PARENT_ITEM_ID
WHERE A.RARITY = 'RARE'
ORDER BY ITEM_ID DESC
\`\`\`

문제:
- `B.ITEM_ID` — 자식 ID (정답)
- `A.ITEM_NAME`, `A.RARITY` — 부모의 이름/희귀도 (잘못)

부모는 RARE라고 이미 알고 있고, **자식의 이름·희귀도가 필요**.
자식의 정보는 ITEM_INFO에 있는데 — 어떻게 가져올지 막힘.

### 핵심 깨달음
ITEM_INFO를 — **부모용과 자식용 두 번 JOIN** 필요.
같은 테이블을 두 번 사용하려면 — 다른 별칭 부여.

## 배운 점

### 같은 테이블 두 번 JOIN
같은 테이블을 다른 역할로 두 번 사용할 때 — **다른 별칭**으로 구분.

\`\`\`sql
ITEM_INFO A    -- 부모 아이템용
ITEM_INFO C    -- 자식 아이템용
\`\`\`

같은 테이블이지만 — 별칭으로 다른 역할 명시.

### 자기 참조 관계 (Self-referencing)
한 테이블이 — 같은 테이블의 다른 행을 참조하는 구조.
- 부모-자식 (이번 문제)
- 매니저-직원 (employee 테이블의 manager_id)
- 댓글-답글

이런 관계 — 같은 테이블 두 번 JOIN 패턴으로 해결.

### 다중 JOIN 구조
관계가 여러 단계일 때 — JOIN 여러 번 사용.

\`\`\`sql
FROM 테이블1 A
JOIN 테이블2 B ON ...
JOIN 테이블3 C ON ...
JOIN 테이블1 D ON ...    -- 같은 테이블도 가능
\`\`\`

이번 문제 — 3단계 JOIN:
1. 부모 아이템 (A)
2. 부모-자식 관계 (B)
3. 자식 아이템 정보 (C, ITEM_INFO 다시)

### JOIN 사고법 — 단계별 추적
복잡한 JOIN은 — 각 별칭이 무엇을 의미하는지 명확히:
\`\`\`
A = 부모 정보
B = A의 자식 찾기 (관계)
C = B의 자식 정보 (실제 데이터)
\`\`\`

이렇게 각 단계를 명확히 — 어떤 데이터가 어디 있는지 추적.

### SELECT의 일관성
\`\`\`sql
SELECT C.ITEM_ID, C.ITEM_NAME, C.RARITY
\`\`\`

`B.ITEM_ID`도 같은 값이지만 — **모든 컬럼을 C로 통일**해서 일관성.
"우리가 원하는 건 자식(C)의 정보"라는 의도 명확.

## 다른 풀이 — 서브쿼리 (참고)
\`\`\`sql
SELECT ITEM_ID, ITEM_NAME, RARITY
FROM ITEM_INFO
WHERE ITEM_ID IN (
    SELECT ITEM_ID 
    FROM ITEM_TREE 
    WHERE PARENT_ITEM_ID IN (
        SELECT ITEM_ID FROM ITEM_INFO WHERE RARITY = 'RARE'
    )
)
ORDER BY ITEM_ID DESC;
\`\`\`

3중 중첩 — JOIN보다 복잡. JOIN 방식이 더 깔끔.

## 종합 활용 — 본인 학습 흐름

- WHERE + ORDER BY 다중
