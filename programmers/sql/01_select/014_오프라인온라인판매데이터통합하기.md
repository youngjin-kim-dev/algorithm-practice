# 오프라인/온라인 판매 데이터 통합하기

[프로그래머스 문제 링크](https://school.programmers.co.kr/learn/courses/30/lessons/131537)

## 문제 요약
ONLINE_SALE과 OFFLINE_SALE 두 테이블에서 — 2022년 3월의 판매 데이터 조회.
- 출력 컬럼: 판매 날짜, 상품ID, 유저ID, 판매량
- OFFLINE_SALE의 USER_ID는 NULL로 표시
- 판매일 오름차순, 상품ID 오름차순, 유저ID 오름차순

## 접근 방법 — UNION 패턴
"두 테이블의 데이터를 하나로 합쳐 출력" → UNION 패턴.
JOIN(옆으로 붙이기) 아님. UNION(위아래로 붙이기).

1. 온라인 판매 데이터 SELECT (2022년 3월 필터)
2. 오프라인 판매 데이터 SELECT (USER_ID 자리에 NULL)
3. UNION ALL로 합치기
4. 마지막에 ORDER BY 한 번

## 풀이
\`\`\`sql
SELECT SALES_DATE, PRODUCT_ID, USER_ID, SALES_AMOUNT
FROM ONLINE_SALE
WHERE YEAR(SALES_DATE) = 2022 AND MONTH(SALES_DATE) = 3

UNION ALL

SELECT SALES_DATE, PRODUCT_ID, NULL AS USER_ID, SALES_AMOUNT
FROM OFFLINE_SALE
WHERE YEAR(SALES_DATE) = 2022 AND MONTH(SALES_DATE) = 3

ORDER BY SALES_DATE, PRODUCT_ID, USER_ID;
\`\`\`

## 막힌 부분

### 1. JOIN으로 시도 — 패턴 자체 잘못
처음에 LEFT JOIN + RIGHT JOIN + UNION으로 시도.
JOIN은 — 두 테이블을 키로 연결할 때 사용. 이번 문제는 — 단순히 두 종류 데이터를 합치는 것.

핵심 깨달음: **JOIN은 옆, UNION은 위아래.**

### 2. OFFLINE_SALE의 USER_ID 컬럼 없음
OFFLINE_SALE에는 USER_ID 컬럼 자체가 없음. UNION하려면 — 양쪽 컬럼 구조가 같아야 함.
해결: `NULL AS USER_ID`로 NULL 직접 넣기.

## 배운 점

### JOIN vs UNION 구분
| | JOIN | UNION |
|---|---|---|
| 방향 | 옆으로 (열 추가) | 위아래로 (행 추가) |
| 조건 | 키로 연결 (ON) | 컬럼 구조 동일 |
| 사용 시점 | 관계 있는 두 테이블 | 같은 종류 데이터 합치기 |

**JOIN 예시**: 게시글 + 댓글 (관계로 연결)
**UNION 예시**: 온라인 + 오프라인 판매 (같은 종류 데이터)

### UNION의 규칙
1. 위·아래 SELECT의 **컬럼 개수, 순서, 자료형** 동일해야 함
2. ORDER BY는 — 합친 후 **마지막 한 번만**
3. 각 SELECT에 ORDER BY 못 씀

### UNION vs UNION ALL
- `UNION` — 중복 제거 (DISTINCT 효과)
- `UNION ALL` — 중복 그대로

판매 데이터 — 중복 제거 의미 없음 → `UNION ALL` 사용.
중복 제거가 필요한 케이스만 `UNION` 사용.

### 한 테이블에 컬럼이 없을 때
\`\`\`sql
SELECT SALES_DATE, PRODUCT_ID, NULL AS USER_ID, SALES_AMOUNT
FROM OFFLINE_SALE
\`\`\`

`NULL AS 컬럼명`으로 — 없는 컬럼 자리에 NULL 넣고 별칭 부여.
양쪽 컬럼 구조 통일 위한 패턴.
