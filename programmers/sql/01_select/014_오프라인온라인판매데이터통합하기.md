# 오프라인/온라인 판매 데이터 통합하기

[프로그래머스 문제 링크](https://school.programmers.co.kr/learn/courses/30/lessons/131537)

## 문제 요약
REST_INFO (식당)와 REST_REVIEW (리뷰) 테이블에서 서울에 위치한 
식당의 정보 + 평균 리뷰 점수 조회.
- 평균점수 소수점 셋째 자리에서 반올림 (소수 둘째 자리까지)
- 평균점수 내림차순, 같으면 즐겨찾기수 내림차순

## 접근 방법
1. 두 테이블 JOIN — REST_ID가 공통 키
2. WHERE로 서울 주소 필터링 (LIKE 와일드카드)
3. AVG로 식당별 평균 → GROUP BY 필요
4. ROUND로 소수 둘째 자리까지 반올림
5. ORDER BY 다중 정렬 (둘 다 DESC)

## 풀이
\`\`\`sql
SELECT A.REST_ID, 
       A.REST_NAME, 
       A.FOOD_TYPE, 
       A.FAVORITES, 
       A.ADDRESS, 
       ROUND(AVG(B.REVIEW_SCORE), 2) AS SCORE
FROM REST_INFO A
JOIN REST_REVIEW B ON A.REST_ID = B.REST_ID
WHERE A.ADDRESS LIKE '서울%'
GROUP BY A.REST_ID
ORDER BY AVG(B.REVIEW_SCORE) DESC, A.FAVORITES DESC;
\`\`\`

## 막힌 부분

### 1. GROUP BY 누락
처음 작성 시 — AVG 사용하면서 GROUP BY 안 함.
식당별 평균 구하려면 — 식당 ID로 그룹화 필수.

### 2. ROUND의 N 의미 헷갈림
처음에 `ROUND(..., 3)` 작성.

문제: "소수점 **셋째 자리에서** 반올림"
→ 소수 2자리까지 결과 → `ROUND(..., 2)`

`ROUND(..., 3)`은 소수 3자리까지 표시 (4자리에서 반올림). 의미 반대.

### 3. LIKE 패턴 너무 광범위 ← 통과 막은 진짜 원인
처음 `LIKE '%서울%'` 사용. 다른 지역에 "서울" 글자 들어간 주소까지 매칭됨.
예: 다른 도시에 있는 "서울대학교 인근 식당" 같은 주소.

해결: `LIKE '서울%'` (서울로 시작하는 주소만).

한국 주소는 시·도가 맨 앞이라 — `'시도이름%'` 패턴이 표준.
이전 강원도 문제와 동일 패턴이지만 — 서울 문제에서 잘못 적용했었음.

### 디버깅 흐름
1. ROUND(..., 3) → ROUND(..., 2)로 수정 → 여전히 통과 안 됨
2. ORDER BY를 별칭/함수로 시도 → 여전히 안 됨
3. LIKE '%서울%' → '서울%'로 변경 → **통과**

진짜 원인은 LIKE 패턴이었음. 한 번에 원인 못 찾고 — 여러 가능성 시도하면서 발견.

## 배운 점

### GROUP BY의 필수성
**집계 함수(AVG, SUM, COUNT, MAX, MIN)와 일반 컬럼을 함께 SELECT할 때 — 
GROUP BY 필수.**

\`\`\`sql
-- 잘못 (모호한 결과)
SELECT REST_ID, AVG(SCORE) 
FROM REVIEW

-- 올바름 (식당별 평균)
SELECT REST_ID, AVG(SCORE) 
FROM REVIEW
GROUP BY REST_ID
\`\`\`

### ROUND 함수의 N 의미

`ROUND(숫자, N)`의 N — **결과로 표시될 소수 자릿수**.

| 코드 | 결과 |
|---|---|
| `ROUND(3.456, 0)` | 3 |
| `ROUND(3.456, 1)` | 3.5 |
| `ROUND(3.456, 2)` | 3.46 |
| `ROUND(3.456, 3)` | 3.456 |

**문제 표현 변환**:
- "소수점 **N째 자리에서** 반올림" → `ROUND(..., N-1)`
- "소수점 **N자리까지** 표시" → `ROUND(..., N)`

이번: "소수점 **셋째** 자리에서 반올림" → 소수 2자리까지 → `ROUND(..., 2)`

### LIKE 패턴 — 한국 주소 표준
한국 주소 형식: "서울특별시 ...", "강원도 ...", "경기도 ..."
시·도가 항상 맨 앞 → `'시도이름%'` 패턴으로 시작 매칭이 표준.

\`\`\`sql
LIKE '서울%'        -- 한국 주소 표준 ✓
LIKE '%서울%'       -- 너무 광범위 (다른 지역의 "서울대학교" 등 매칭)
\`\`\`

**규칙: 한국 주소 시·도 매칭은 `'시도%'` 사용.**

이전 강원도 문제(`'강원도%'`)에서는 정확히 사용했는데 — 
서울 문제에서 무의식적으로 `'%서울%'`로 광범위하게 작성. 
같은 카테고리(시·도) 패턴은 일관되게 적용해야 함.

### 디버깅 — 한 번에 원인 못 찾음
이번 시행착오:
1. ROUND 수정 (안 됨)
2. ORDER BY 수정 (안 됨)
3. LIKE 수정 (통과)

여러 가능성을 차례로 검증하는 사고법이 — 디버깅 핵심.
