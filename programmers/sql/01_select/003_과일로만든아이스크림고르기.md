# 과일로 만든 아이스크림 고르기

[프로그래머스 문제 링크](https://school.programmers.co.kr/learn/courses/30/lessons/133025)

## 문제 요약
- FIRST_HALF (상반기 출하 정보)와 ICECREAM_INFO (성분 정보) 두 테이블
- 상반기 총주문량(TOTAL_ORDER) 3000 초과
- 주성분(INGREDIENT_TYPE)이 fruit_based
- 위 조건 만족하는 아이스크림 맛(FLAVOR)을 총주문량 내림차순으로 조회

## 접근 방법
두 테이블에서 데이터를 조합해야 함.
- FLAVOR가 두 테이블의 공통 컬럼 (FK 관계)
- 방법 1 — JOIN으로 두 테이블 결합
- 방법 2 — 서브쿼리로 한 테이블 결과를 다른 테이블의 WHERE 조건에 사용

## 풀이 1: JOIN

\`\`\`sql
SELECT A.FLAVOR
FROM FIRST_HALF A
JOIN ICECREAM_INFO B ON A.FLAVOR = B.FLAVOR
WHERE A.TOTAL_ORDER > 3000
  AND B.INGREDIENT_TYPE = 'fruit_based'
ORDER BY A.TOTAL_ORDER DESC;
\`\`\`

**해석**:
1. FIRST_HALF에 별칭 A, ICECREAM_INFO에 별칭 B
2. FLAVOR 기준으로 INNER JOIN (양쪽 테이블에 다 있는 FLAVOR만)
3. WHERE로 두 조건 필터링
4. ORDER BY DESC로 총주문량 내림차순

## 풀이 2: 서브쿼리

\`\`\`sql
SELECT FLAVOR
FROM FIRST_HALF
WHERE TOTAL_ORDER > 3000
  AND FLAVOR IN (
    SELECT FLAVOR
    FROM ICECREAM_INFO
    WHERE INGREDIENT_TYPE = 'fruit_based'
  )
ORDER BY TOTAL_ORDER DESC;
\`\`\`

**해석**:
1. 안쪽 서브쿼리 — ICECREAM_INFO에서 fruit_based인 FLAVOR 목록 추출
2. 바깥쪽 — FIRST_HALF에서 TOTAL_ORDER > 3000이면서, 추출된 FLAVOR 목록에 포함된 행만
3. ORDER BY DESC로 정렬

## JOIN vs 서브쿼리 — 어느 게 좋은가
**일반적으로 JOIN 추천:**
- 실무 표준 — 두 테이블 데이터 조합 시 JOIN이 압도적으로 많이 사용됨
- 성능 — DB 옵티마이저가 JOIN을 더 효율적으로 처리하는 경우가 많음
- 가독성 — 두 테이블 관계가 한눈에 보임

**서브쿼리가 적합한 경우:**
- 한쪽 테이블의 데이터만 SELECT 결과로 필요할 때
- 결과를 단순히 필터링 조건으로만 사용할 때
- JOIN하면 중복 행이 생길 수 있는 상황

## 배운 점
- JOIN 조건은 `ON` 키워드 사용 (`IN`이 아님)
- 두 테이블에 같은 이름의 컬럼이 있을 때 — `A.FLAVOR`처럼 별칭으로 명시
- INNER JOIN의 INNER는 생략 가능 (`JOIN`만 써도 INNER JOIN)
- 서브쿼리에서 `IN` 연산자 — 결과 목록에 포함되는지 확인할 때 사용
- 같은 문제를 JOIN과 서브쿼리 두 가지로 풀 수 있음
